# 描画ベンチマークの実装計画（Bash版）

- 独立CLIを `scripts/benchmark-rendering.sh` とし、macOS標準のBash 3.2に対応する。
- Git、Homebrew、SwiftPMはBashから直接呼び出す。JSONはjq、Info.plistはplutilで読む。Pythonとyqは実行依存に含めない。
- 固定Swiftテンプレートで計測し、POSIX awkでログの完全性検証、中央値・p95・初回時間・倍率の計算、CSVとMarkdown生成を行う。
- 引数なしではbrewのインストール版とアプリのバージョンを照合し、ローカルの対応タグを使う。`--baseline-ref`ではbrewを使わない。不一致、参照不在、未対応APIは停止する。
- 作業ツリーの未コミット変更を含むソースと比較元を別々に保存し、各Package.resolvedの固定リビジョンとチェックアウトを照合してReleaseビルドする。アプリの公開APIは変更しない。
- 1080p/4K、図形1/20/100、線幅6/24、先頭/中央/末尾を使用する。図形1個の重複を除外して28条件。各35回、先頭5回を除外し、通常描画2種と現在のキャッシュ描画の84組・2940サンプルを必須とする。
- 毎回一意な `build/benchmarks/<日時>-<接尾辞>/` にスナップショット、Git差分、環境、ログ、生データ、比較を保存する。比較対象は逐次実行し、性能閾値は設けない。
- 対応ソースの再ビルド比較でありインストール済みバイナリの計測ではないこと、描画内容の差、ベース画像なし、UI処理・画面転送を含まないことをレポートに記載する。
- プロジェクトSkillとREADMEをBash CLIの呼び出しに統一する。

検証はBash構文チェック、ShellCheck、既知の値を使うawk集計テスト、欠落・重複・不正ログと存在しない参照の失敗確認、CLIの標準実行と明示参照での再実行を行う。過去結果と元ソースのハッシュが維持されることを確認する。Skill用quick_validate.pyは開発用検証ツールであり、CLIの依存には含めない。
