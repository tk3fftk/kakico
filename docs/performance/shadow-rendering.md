# 影描画の局所最適化

四角・楕円は塗りと線を一つの影として合成するため、透明レイヤーを維持する。
レイヤーの範囲を図形の矩形＋線幅の半分＋ぼかし・ずれ・アンチエイリアスの余白に限定する。
線・矢印は単一の描画命令なので、直接影付きで描く。
矢印にはレイヤーやクリップ矩形を設けないため、`boundingBox()` に入らない矢尻も `arrowOutline()` の全頂点が描画される。
影のパラメーター、公開API、保存形式、キャンバスと書き出しの共通処理は維持する。

## 再現方法

```sh
swift test
SHADOW_BENCHMARK=1 swift test -c release --filter ShadowOptimizationTests
```

`ShadowReferenceRenderer` は変更前の図形描画を保存したテスト専用の参照実装。
影なしモードは影追加前と同じ描画命令を影・レイヤーなしで実行する。
影追加前のコミット自体をチェックアウトした比較ではない。
画像比較は透明背景でRGBA全チャンネルを比較し、倍率1/2、線幅6/24/48、斜め矢印、半透明の塗りと線、重なりを検証する。
さらに4種類それぞれを中央と四隅へ配置する。
直接描画とグループ合成の丸め差を許容するため、最大差4/255、全チャンネル平均差0.15/255以下を要求する。

性能計測はsRGB RGBAビットマップへの `Renderer.draw` を対象とし、コンテキスト作成・クリア・モデル変更の時間を除く。
図形は矢印・線・四角・楕円の順に配置し、先頭の矢印の位置と終点を毎フレーム変える。
各条件でウォームアップ5回、計測30回を行い、中央値とnearest-rank p95（昇順29番目）をmsで出力する。
1080p/4K、図形1/20/100個、線幅6/24の12条件で比較する。
画面への転送、SwiftUI/AppKit、ベース画像の描画、`flatten` の画像生成時間は含まないため、実アプリのフレーム時間とは区別する。

全12条件で中央値は半分以下になった。1080p・20図形のp95は線幅6で2.38ms、24で5.53msで、描画処理の16ms目標を達成した。
変更前は解像度を上げると時間が大幅に増え、最適化後はほぼ同じ時間に収まる。広い透明レイヤーの処理が主な負荷だったという仮説と整合する。
ただし100図形・線幅24ではp95が35〜41ms残る。次の改善候補は、確定図形をキャッシュし、操作対象だけを毎フレーム描画する方式。
本計測だけでは実アプリ全体の16ms以内を保証しない。
